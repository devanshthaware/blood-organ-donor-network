# VeinLink — Organ Domain Model Specification

## 1. Domain Entities & Schemas

### 1.1 `organDonors`
Represents an individual registered as an organ donor.
```typescript
{
  userId: string,                   // Clerk User ID / Reference to users table
  donorStatus: OrganDonorStatus,    // "REGISTERED" | "PENDING_VERIFICATION" | "VERIFIED" | "ACTIVE" | "INACTIVE" | "SUSPENDED"
  donationPreferences: string[],    // Array of supported ORGAN_TYPES ("KIDNEY", "LIVER", etc.)
  verificationStatus: VerificationStatus, // "UNVERIFIED" | "PENDING" | "VERIFIED" | "REJECTED"
  bloodType?: string,               // ABO/Rh blood group
  location: {
    lat: number,
    lng: number,
    address?: string
  },
  registeredAt: number,             // Epoch timestamp
  updatedAt: number,                // Epoch timestamp
  metadata?: any                    // Additional non-clinical demographic info
}
```

### 1.2 `consentRecords`
Maintains legal auditability of donation consent. Registration alone is never treated as consent.
```typescript
{
  donorId: string,                  // Reference to organDonors or userId
  consentType: "OPT_IN" | "ORGAN_SPECIFIC" | "FIRST_PERSON" | "SURROGATE",
  status: ConsentStatus,            // "NO_CONSENT" | "PENDING" | "GRANTED" | "WITHDRAWN" | "EXPIRED_OR_INVALID"
  witnessName?: string,             // Verifying coordinator / witness
  recordedAt: number,
  updatedAt: number,
  source: string,                   // e.g. "REGISTRY_PORTAL", "CLINICAL_COORDINATOR"
  version: string,                  // Consent legal form version
  withdrawnAt?: number,             // Timestamp if revoked
  notes?: string
}
```

### 1.3 `recipients`
Represents a patient registered on the regional or national organ transplant waiting list.
```typescript
{
  userId: string,                   // Clerk identity
  recipientStatus: RecipientStatus, // "REGISTERED" | "PENDING_VERIFICATION" | "ACTIVE" | "MATCHED" | "ALLOCATED" | "COMPLETED" | "INACTIVE" | "WITHDRAWN" | "SUSPENDED"
  requiredOrganType: string,        // e.g. "KIDNEY", "HEART"
  bloodType: string,                // ABO/Rh compatibility key
  urgency: "LOW" | "MEDIUM" | "HIGH" | "CRITICAL",
  verificationStatus: VerificationStatus,
  hospitalId: string,               // Attending hospital
  transplantCenterId?: string,      // Assigned specialized transplant facility
  location: {
    lat: number,
    lng: number,
    address?: string
  },
  registeredAt: number,
  updatedAt: number
}
```

### 1.4 `organInventory`
Tracks an identified, recovered, or in-transit organ. Each organ is a distinct physical entity with an expiring preservation deadline.
```typescript
{
  organType: string,                // e.g. "KIDNEY", "LIVER"
  bloodType: string,                // ABO/Rh key
  status: OrganInventoryStatus,     // "IDENTIFIED" -> "VERIFIED" -> "AVAILABLE" -> "MATCHING" -> "ALLOCATED" -> "IN_TRANSIT" -> "TRANSPLANTED"
  donorId?: string,                 // Originating organ donor reference
  currentFacilityId: string,        // Current hospital or center holding organ
  availabilityTimestamp: number,    // Epoch ms when organ became available
  preservationDeadline: number,     // Epoch ms cutoff for cold ischemia preservation
  verificationStatus: VerificationStatus,
  viabilityNotes?: string,
  createdAt: number,
  updatedAt: number
}
```

### 1.5 `organRequests`
Represents an accredited hospital or transplant center's formal requisition for an organ.
```typescript
{
  requestingOrganizationId: string, // Hospital or Transplant Center ID
  recipientId: string,              // Reference to recipients record
  organType: string,
  bloodType: string,
  urgency: "LOW" | "MEDIUM" | "HIGH" | "CRITICAL",
  status: OrganRequestStatus,       // "CREATED" -> "ACTIVE" -> "MATCHING" -> "ALLOCATED" -> "COMPLETED"
  notes?: string,
  createdAt: number,
  updatedAt: number
}
```

### 1.6 `organMatches` (Advisory Recommendation)
Candidate pairings generated by the matching system. Never converts automatically to an allocation.
```typescript
{
  organId: string,                  // organInventory reference
  recipientId: string,              // recipients reference
  requestId: string,                // organRequests reference
  compatibilitySummary: {
    bloodCompatibility: boolean,
    distanceKm: number,
    waitingTimeScore?: number
  },
  score: number,                    // Composite candidate ranking score
  ranking: number,                  // Priority position in candidate list
  constraints: string[],            // Applied constraints (distance, ABO)
  explanation: string,              // Clinical rationale for coordinator review
  modelVersion: string,
  status: OrganMatchStatus,         // "PROPOSED" | "REVIEWING" | "ACCEPTED_FOR_ALLOCATION" | "REJECTED_BY_COORDINATOR" | "SUPERSEDED"
  createdAt: number,
  updatedAt: number
}
```

### 1.7 `organAllocations` (Binding Authorized Decision)
A formal decision assigning an organ to a recipient. Requires authorized human coordinator review.
```typescript
{
  organId: string,                  // Assigned organInventory
  recipientId: string,              // Target recipients record
  requestId: string,                // Associated organRequests
  matchId: string,                  // Reference to the organMatches record reviewed
  decisionStatus: AllocationStatus, // "PENDING_HUMAN_APPROVAL" | "APPROVED" | "REJECTED" | "CANCELLED" | "EXECUTED"
  decisionReason: string,           // Mandatory clinical justification
  decisionMakerId: string,          // Clerk ID of authorizing medical coordinator
  decisionMakerRole: string,        // Role (e.g. "hospital", "admin")
  approvedAt?: number,              // Timestamp of approval commit
  policyVersion: string,            // e.g. "1.0-NATIONAL-ALLOCATION-POLICY"
  auditReference: string,           // Immutable unique verification token
  createdAt: number,
  updatedAt: number
}
```

### 1.8 `transplantCenters`
Accredited facilities authorized to perform transplant surgeries and organ recovery.
```typescript
{
  name: string,
  hospitalId: string,               // Underlying healthcare institution
  address: string,
  region: number,
  lat: number,
  lng: number,
  accreditationCode: string,
  supportedOrgans: string[],        // Array of organ types authorized for transplant
  isActive: boolean,
  createdAt: number
}
```

---

## 2. Controlled Organ Types

To eliminate free-text discrepancies, all organ classifications are constrained to the controlled `ORGAN_TYPES` enum:
- `KIDNEY`
- `LIVER`
- `HEART`
- `LUNGS`
- `PANCREAS`
- `CORNEA`
- `INTESTINE`
- `TISSUE`
